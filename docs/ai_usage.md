# Использование и проверка ИИ

ИИ применялся как помощник при анализе и подготовке SQL. Ответ ИИ не считается доказательством: решение проверяется на данных, исходном коде и тестах. Ниже зафиксирован проверенный эпизод интеграции; личные примеры остальных участников нужно добавить только после их подтверждения.

## Проверенный эпизод: повторные покупатели

При интеграционной проверке ассистент обнаружил, что исходный запрос повторных покупок учитывал только заказы со статусом `delivered`. Для вопроса №4 согласован расчёт по заказам всех статусов и группировка по `customer_unique_id`.

Проверка выполнялась на отдельной базе с копией исходных данных: до исправления запрос возвращал 93 358 покупателей и 3,00% повторных, после исправления — **96 096 покупателей, 2 997 повторных, 3,12%**. Фактический запрос и контроль его результата находятся в [`queries/04_retention.sql`](../queries/04_retention.sql) и [`tests/40_official_answers.sql`](../tests/40_official_answers.sql). Контрольное число подтверждает результат на текущей выгрузке; выбор всех статусов — отдельное соглашение команды.

Это пример того, как результат анализа ИИ проверяется выполнением SQL. Он не подтверждает, кто из участников первоначально написал запрос или как именно использовал ИИ.

## Проверки, полезные при работе с ИИ

- **Ключи отзывов.** `review_id` повторяется: в 99 224 исходных строках 98 410 различных значений. Проверенная на текущей выгрузке пара `(review_id, order_id)` используется как первичный ключ. Установка отдельного `PRIMARY KEY (review_id)` при дубликатах вызвала бы ошибку; потеря строк возможна только при дополнительной дедупликации или игнорировании конфликтов.
- **Соединение фактов.** Прямое внутреннее соединение позиций с платежами по заказу увеличивает сумму товарной выручки доставленных заказов с 13 221 498.11 до 13 813 828.71 и исключает заказ без платежа. Для сверки платежи и позиции сначала агрегируют отдельно по заказу. Проверка — сценарий 3 в [`tests/20_reconciliation.sql`](../tests/20_reconciliation.sql).
- **Уровень среднего чека.** На текущей выгрузке средняя цена доставленной позиции — 119.98, средний полный чек заказа — 159.88. Сначала нужно получить сумму каждого заказа, включая доставленные заказы без позиций, затем усреднить. В сценарии 6 финансового QA равенство средних считается ошибкой; это ограничение теста, поскольку на другом наборе совпадение может быть корректным. Проверка фактического ответа также есть в [`tests/40_official_answers.sql`](../tests/40_official_answers.sql).

Эти три проверки описывают возможные ошибки и фактическое поведение модели. Без дополнительных свидетельств они не приписываются конкретным участникам или предложениям ИИ. Документ может быть дополнен подтверждёнными примерами участников №2–5: исходное предложение, проверка, решение и ссылка на результат.
