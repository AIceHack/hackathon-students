# Архитектурные решения

Контракт требует подтверждения участников. Сборка и контрольные ответы
проверены на отдельной базе с копией исходных данных.

- Заказ и его позиции разделены: у заказа один покупатель, у позиций — свои
  товары, продавцы, цена и доставка. Это сохраняет правильный уровень расчётов.
- Платежи и отзывы остаются отдельными фактами. Перед соединением суммы
  платежей и позиций группируются по заказу, чтобы не размножать деньги.
- Заказы связаны с покупателями по `customer_id`; повторные покупки считаются
  по `customer_unique_id`. Первичные ключи платежей и отзывов составные;
  уникальность пар подтверждена на исходной выгрузке.
- Отсутствующая категория получает отдельный код; категория без перевода
  сохраняет исходное имя. Неизвестные даты и характеристики остаются NULL.
- `raw` — неизменяемый источник. Сборка пересоздаёт `core` и `mart` в одной
  транзакции, проверяет целостность и снимок `raw`. История переходов статусов
  и данные о возвратах из текущей выгрузки не восстанавливаются.
